# ADR-001: 재작성 대신 공개 헤더와 내부 선언 정리

상태: 적용·검증 완료. 날짜: 2026-10-06.

## 판단 근거

핵심 FSM과 모듈 호출은 이미 구현되어 있고 모듈 분리본·통합본의 동일한 134개 테스트, 통합본 독립 컴파일과 CLI 비교가 통과했다. 현재 읽기 어려운 부분은 통합 헤더에 공개 API 7개, 내부 함수 18개, 모의 장치 함수 5개 및 설명이 한꺼번에 들어간 점이다. 검증된 동작을 다시 설계할 필요가 확인된 상태는 아니다.

| 선택 | 필요한 작업 | 비용·위험 |
|---|---|---|
| 처음부터 재작성 | FSM, 타이밍, 입출력 순서, API, 오류 경로, 테스트 연결과 문서 모두 다시 작성·대조 | 현재 확인된 문제보다 범위가 크고 기존 동작과 달라질 위험이 높음 |
| 기존 코드 정리 | 공개 선언과 내부 선언 분리, 주석·읽기 순서 정리, 미사용 표시 일부 제거, 기존 시험 재실행 | 함수와 검증 근거를 재사용하므로 현재 상태에서 비용과 변경 위험이 더 작음 |

## 결정

- 제출용 구현 형태는 controller.c와 controller.h 두 파일을 유지한다.
- controller.h에는 외부 API 7개와 이에 필요한 센서·상태·장치 연결 타입만 둔다.
- 내부 모듈·모의 장치 선언은 controller.c로 이동한다. 함수와 호출 관계는 유지한다.
- 기존 직접 모듈 검사를 유지하기 위한 tests/single_file_test_support.h는 같은 생성기가 내부 선언에서 만든다. 일반 프로그램은 이 파일을 사용하지 않는다.
- 함수 심볼의 링크 방식은 유지한다. 불필요한 시험용 visibility 매크로나 새 계층을 만들지 않는다.
- 사용되지 않는 예약 오류 이름과 읽히지 않는 좌·우·먼지 valid 필드를 정리한다. 기존 오류 숫자값, 전방 캐시 valid, Enable/Disable 기록은 유지한다.
- Ctrl+C·출력 저장 실패 등 별도 오류 처리 보완은 이번 구조 정리에 섞지 않는다.

## 단계와 검증

1. 현재 커밋과 실행 파일을 작업용 review_cleanup_20261006에 보관한다.
2. 생성기에서 공개·내부 선언을 분리하고 7개 공개 함수에 짧은 한국어 계약 설명을 남긴다.
3. 관련 소스의 미사용 항목을 정리한 후 통합본과 시험 지원 헤더를 함께 생성한다.
4. CMake·테스트 include와 사용 설명을 새로운 경계에 맞춘다.
5. 모듈 분리본·통합본의 기존 GoogleTest를 실행한다. 기대값을 새 구현에 맞춰 바꾸지 않는다.
6. 두 제품 파일만 빈 디렉터리로 복사하여 엄격 C17 컴파일을 확인하고, 정리 전 실행 파일과 9개 CLI 사례를 비교한다.
7. 정리 전후 공개 선언 수·헤더 길이와 실제 결과를 기록하고 팀 공유 저장소에 반영한다.

원본 과제와 과제 제출용 폴더는 변경하지 않는다. 최종 SD PPT/PDF와 미확정 요구 해석은 별도 작업으로 남는다.

## 결과

공개 헤더는 314줄·함수 선언 30개에서 99줄·공개 함수 7개로 줄었다. 일반 실행에 필요한 프로젝트 파일은 여전히 controller.c와 controller.h 두 개다. GoogleTest 134개를 두 빌드 형식에서 각각 통과했고, 엄격 C17 독립 컴파일과 정리 전 실행 파일 대비 9개 CLI 사례도 모두 통과했다. 자세한 근거와 범위는 [통합본 검증 기록](../single_file/VERIFICATION.md)에 있다.
