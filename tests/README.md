# RVC 기능 테스트

`rvc_tests.cpp`는 GoogleTest v1.15.2를 사용하는 C++17 테스트 실행기다. 제품 소스는 C17로 따로 컴파일하며 C 연결 규약으로 호출한다. 2026-10-04에 사용자가 전달한 Team Project #2 공지는 테스트 프레임워크를 팀별 자율로 정한다. 이 프로젝트는 GoogleTest를 선택했다. 개별 모듈 검사와 시스템 동작 검사를 구분하고, 별도의 시스템 시험 보고서를 PPT/PDF에 포함해야 한다. [제출 조건 대조](../docs/STATUS.md)를 참조한다.

## 실행과 근거

프로젝트 루트의 `build.ps1` 또는 CMake 테스트 타깃으로 빌드·실행한다. 실제 실행 성공 여부와 개수는 빌드 결과 및 GoogleTest 결과 파일을 확인한다. 이 문서의 시나리오 목록 자체는 실행 성공 기록이 아니다.

현재 테스트 구성은 134개다. 성공 여부는 직접 실행한 결과로 확인한다. Windows 빌드 스크립트는 `results/gtest.xml`에, 직접 CTest를 실행하면 빌드 폴더의 `gtest.xml`에 실제 결과를 저장한다.

프로젝트 폴더에서 PowerShell로 전체 빌드·검사·시나리오를 실행한다.

```powershell
.\build.ps1
```

개별 테스트 이름과 상세 PASS/FAIL을 보려면 빌드 후 다음을 사용한다. 기본 도구 경로를 변경했다면 PATH도 그 경로로 맞춘다.

```powershell
$env:PATH = 'C:\msys64\ucrt64\bin;' + $env:PATH
.\build\cmake\rvc_tests.exe --gtest_list_tests
.\build\cmake\rvc_tests.exe
# 회전·후진 시간 경계 6개만 실행
.\build\cmake\rvc_tests.exe '--gtest_filter=TurnAndBackBoundaries/TimingTest.*'
# 먼지 미감지 시 일반 청소 복귀만 실행
.\build\cmake\rvc_tests.exe '--gtest_filter=RobotTest.DustLossImmediatelyRestoresNormalCleaningWithoutMotorWrite'
```

목록 조회는 검사를 실행하지 않는다. 선택 실행 결과는 전체 통과 결과로 해석하지 않는다. `build.ps1`이 전체 실행의 XML과 요약을 `results`에 저장한다. CTest의 `1/1`은 등록된 테스트 실행기 1개이며, 그 안에서 실제 GoogleTest 사례 134개가 실행된다.

## 입력 이력과 기대 결과 예시

아래 예시는 자동 테스트에 포함된 계약을 설명한다. 실제 입력·단언은 `rvc_tests.cpp`에서 확인한다.

| 시나리오 | 준비와 입력 | 기대 결과 |
|---|---|---|
| 먼지 감지·해제 | 전진 중 D=1, 다음 Tick D=0 | 강화 후 일반 청소 복귀, 불필요한 모터 재명령 없음 |
| 전방 장애물 | 전진·청소 중 F=1, R=0 | 청소 OFF 후 RIGHT 명령, 회전 진입 e=0 |
| 회전 경계 | 회전 진입 후 앞이 열린 입력 유지 | 후속 1~4 Tick은 회전 유지, 5번째에 전진 선택 |
| 후진 경계 | 세 방향 막힘으로 후진 진입 후 앞·오른쪽을 개방 | 후속 3번째 Tick에 우회전 선택, 직접 전진하지 않음 |
| 센서 오류 | 정상 동작 중 주기 센서 읽기 실패 주입 | IO_ERROR, OFF/STOP 시도, 다음 Tick은 NOT_READY |

기대 결과는 [구현 설계](../docs/06_implemented_design.md)의 결정표와 계약에 따라 작성했다. 6개 동작 상태 각각에서 F/L/R/D의 16개 조합을 검사하는 96개 경계 사례는 테스트 파일에 별도의 상수 정답표를 둔다. 생산 Controller의 분기 함수를 호출해서 기대값을 만들지 않는다.

## 검사 방식

- 모의 센서값 주입 → 공개 전방 보고 → `rvc_tick()` 호출 → 상태 및 실제 장치 콜백 로그 비교.
- 모든 FSM 상태는 초기화와 센서 입력 이력으로 도달한다. 내부 상태나 카운터를 임의로 설정하지 않는다.
- 회전 진입은 e=0, 5번째 후속 Tick에 완료한다. 후진은 3번째 후속 Tick에 완료한다.
- 유지 중에는 장치 재명령이 없고, 같은 회피를 다시 시작할 때에는 해당 Motor Trigger를 다시 전달한다.
- 회피 직전 청소가 ON/UP이면 OFF를 모터 방향 명령보다 먼저 보낸다. 이미 OFF이면 중복 OFF를 생략한다.
- 전진 상태에서 먼지가 사라진 첫 Tick에 일반 청소로 복귀한다. 별도 먼지 유지 타이머는 없다.
- 초기화는 Stop → Off, 명시적 종료·오류 처리는 Off → Stop을 각각 시도한다.
- 장치 실패는 성공 이벤트를 기록하지 않는다. 실패 이후 미준비 상태를 유지하고 재초기화를 요구한다.
- 일부 하위 모듈 시험에서는 내부 헤더의 함수를 직접 호출하여 Disable/Stop 차이, enum 검증, 실패 시 출력 인자 보존을 검사한다. 내부 상태 구조체는 공개하지 않는다.

## 모의 장치

`adapters/mock/mock_device.h`의 `RvcMockDevice`는 인스턴스별 센서 입력, 읽기/쓰기 시도 횟수, 성공 출력의 순서 로그를 가진다. `rvc_mock_fail_next()`로 특정 작업의 다음 N회를 실패시킬 수 있다. `rvc_mock_clear_events()`는 로그만 비우며 출력값·횟수·고장 주입은 유지한다.

로그는 1,024개까지 저장하며 가득 찬 뒤의 출력은 `RVC_IO_ERROR`다. 테스트마다 객체와 모의 장치를 새로 만든다. 테스트는 실제 시간을 기다리지 않는다.

## 범위와 한계

센서 조합, 타이머 경계, 호출 순서·횟수, 오류, 재초기화, 복수 인스턴스를 검증한다. 실제 모터 하드웨어, 운영체제 스케줄러의 실시간 보장, 병렬 ISR 호출, 모든 무한 입력 이력, 수업의 비공개 채점 기준을 검증한 것은 아니다. 이벤트는 직렬 호출한다.
